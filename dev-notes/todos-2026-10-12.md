## C. Claude Code mods

Decision: **not yet.**

- Probe (2026-10-12, headless): a mod in a trusted project's
  `.claude/skills/<mod>/` loads as `<mod>@skills-dir` with no flag; the same mod
  in an untrusted directory did not. Interactive sessions untested.
- A display-only mod (status line, pane, band) costs 0 tokens. One that adds
  prompt or system-prompt text costs tokens every turn. Neither reduces usage by
  itself; the savings come from `/clear` and reading less.
- The only gain worth having is a live status line (branch, spec step, budget).

If it is ever built:
- [ ] Verify project-level loading in an interactive, trusted session.
- [ ] `install.sh`: a declared list of mod folders, so they are not reported as
  "kept, not from this pack".
- [ ] A `check.sh` rule: every shipped mod is named by a doc, and validates.
- [ ] A test file that runs `claude plugin validate` and `claude plugin test`;
  the bash suite cannot exercise a mod.

Revisit when someone runs `progress` only to see state.

## D. Role agents
