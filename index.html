    What holds it together

    Every piece of state is a file.

    Plans, the current spec with its ticked steps, and open findings load at the start of every session. A cold start is the normal case, and “continue” picks up at the first unchecked step.

    Findings block the merge.

    review records each finding with a durable ID, a severity and a status. An open or fixed P0 or P1 stops ship. A repair is not done until a review has seen the result.

    Evidence, or it didn’t happen.

    “Passes” names a command, its output, or a screenshot. “I couldn’t verify that” is an accepted answer, and verify reports it per criterion.

    Every skill checks its inputs first.

    Each one opens by naming what must already be true and what to run when it is not. A skill that stops is refusing to build confident output on an empty file.

    Work only you can do is written down.

    An account, a card, a device, a decision: skills record it in needs-you.md with what it blocks and when. prepare lists it, and preflight treats anything required and open as a blocker.

    Your standards win.

    Conventions that hold on any stack belong to the pack and refresh on every install. Everything specific to your project is yours, is never overwritten, and takes precedence where the two disagree.

    Works in the tool you already use

    Skills refer to each other by plain name, never by one tool’s command syntax, so the same files read correctly everywhere.

    Claude Code

    Finds the skills through .claude/skills, a link to the one installed copy. Type /spec.

    opencode

    Reads AGENTS.md and the skills directly. The generated command wrappers let you type /spec there too.

    No AI tool at all

    Every skill is a numbered worksheet. Open spec/SKILL.md and work through Step 1, then Step 2.

    Install

    Nothing to build and no network calls. It needs bash, python3 and the usual Unix tools.

    1. Clone the pack

      git clone https://github.com/habr33/ai-project-starter.git ~/ai-project-starter

    2. Put it on your PATH (optional)

      echo 'export PATH="$HOME/ai-project-starter:$PATH"' >> ~/.bashrc && exec bash

    3. Create a project

      new-project.sh my-app && cd my-app

      Open it with your AI tool and run ideate. To update later, git pull in the clone, then run install.sh in the project. Files you own are never touched.

    Already have a project?

    Run install.sh inside it, then setup. It reads the real repo, records the stack and commands that are actually there, and installs nothing.

    Building a backend and front ends in parallel?

    new-project.sh shop --parts web,api gives each part its own loop and state. Most projects should stay single-part; the multi-part guide says when not to.
